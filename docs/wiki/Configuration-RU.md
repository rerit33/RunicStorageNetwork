# Настройки

Для Runic Storage Network **1.0.0**. [English version](https://github.com/rerit33/RunicStorageNetwork/wiki/Configuration).

Назначение построек, радиусы и материалы собраны на странице [Постройки, радиусы и рецепты](https://github.com/rerit33/RunicStorageNetwork/wiki/Buildings-and-recipes-RU).

Файл конфигурации: `BepInEx/config/local.runicstoragenetwork.cfg`. Он появляется после первого запуска мода. При использовании менеджера модов редактируйте файл того профиля, с которым играете.

Параметры `Network`, `Containers`, `Building` и `Content` в мультиплеере доступны администратору и синхронизируются через Jötunn. Их значения для сессии определяет сервер. Изменения через систему конфигурации применяются во время игры; простое редактирование файла на диске не гарантирует его немедленной перечитки. Самый простой способ применить правки файла — сделать их при закрытой игре/остановленном сервере, затем запустить снова.

Разделы `Experimental` и `Diagnostics` настраиваются отдельно в каждой установке. Изменение экспериментальной настройки только на сервере **не включает** её у клиентов.

## Экспериментальные удалённые хранилища

> **Новое в 1.0:** Удалённые хранилища и API включены по умолчанию в новых конфигурациях. Для отключения установите `ExperimentalUnloadedNetworks = false` и перезапустите игру. При обновлении сохранённые значения не меняются.

```ini
[Experimental]
ExperimentalUnloadedNetworks = true
```

Значение `ExperimentalUnloadedNetworks = true` разрешает работу подключённой сети и подходящих хранилищ вне области загрузки игрока. Если в старом конфиге стоит `false`, измените его на `true` и перезапустите игру. Параметр также включает [API для других модов](https://github.com/rerit33/RunicStorageNetwork/wiki/API). Для Рунических мостов дополнительно нужен `RunicGatewayEnabled = true`. Мост использует локальные радиусы хранилищ, снабжения и связи от реле; расстояние не ограничивается только между парой мостов. При выключении функции построенные мосты остаются видимыми, но не снабжают ресурсами и не работают как реле.

Для мультиплеера установите одинаковую версию RSN у хоста или на выделенном сервере и у всех игроков, затем включите параметр **в каждой установке**. После изменения полностью перезапустите все клиенты и хост/сервер. Для отключения верните `false` везде и перезапустите. Если параметр выключен на сервере, клиенты используют обычную сеть в загруженной области, а экспериментальный API недоступен.

Система использует сохранённые записи сети и инвентарей, не удерживая всю базу загруженной. Посещать ядро после входа в мир не требуется. Обнаружение начинается при обращении к сети, поэтому первый запрос может занять время. Это не запускает работу остальных устройств и симуляцию мира вне области загрузки.

Ванильные и подходящие модовые хранилища используют общие фильтры контейнеров. Если инвентарь нельзя безопасно прочитать и сохранить в таком режиме, удалённый доступ к нему недоступен. Нестандартные хранилища требуют отдельной проверки. Новый API проверен в одиночной игре рядом с ядром и при выгруженном ядре; его интеграция в мультиплеере ещё тестируется.

## Дополнительный контент

Контент доступен только при значении `true` своего переключателя. Все три параметра по умолчанию включены; в мультиплеере их определяет сервер.

```ini
[Content]
StorageCodexEnabled = true
BuildersCodexEnabled = true
RunicGatewayEnabled = true
```

| Параметр | Что происходит при `false` |
| --- | --- |
| `StorageCodexEnabled` | Скрывается рецепт постройки Кодекса запасов, отключаются его окно хранилища и выдача ресурсов. |
| `BuildersCodexEnabled` | Скрывается рецепт экипируемого Кодекса строителя, отключаются привязка и дополнительный радиус снабжения для строительства. |
| `RunicGatewayEnabled` | Скрывается рецепт Рунического моста, мосты исключаются из маршрутов сети. |

Созданные предметы, постройки и сохранённые привязки остаются. Верните `true`, чтобы восстановить их функции. Обычный Рунный кодекс, используемый как ингредиент, не затрагивается. Только мостам также нужны экспериментальные удалённые сети; Кодекс запасов и Кодекс строителя работают с обычной сетью в загруженной области.

## Сеть

Расстояния указаны в метрах. Увеличение радиусов может добавить в сеть больше узлов и сундуков и увеличить объём работы при её проверке.

| Параметр в `[Network]` | По умолчанию | Допустимо | Назначение |
| --- | --- | --- | --- |
| `SupplyEnabled` | `true` | `true` / `false` | Включает снабжение из сети. При отключении постройки остаются доступны, но новые списания через API также прекращаются. |
| `GatewayCarriesAllItems` | `false` | `true` / `false` | Разрешает Руническим мостам переносить любые предметы, включая руду и металлические слитки. |
| `StorageRadius` | `20` | `1`–`100` | Радиус подключения хранилищ к ядру. |
| `SupplyRadius` | `20` | `1`–`100` | Радиус снабжения крафта, строительства и доступа к хранилищу вокруг ядра. |
| `RelayLinkRange` | `50` | `1`–`100` | Максимальное расстояние между соединёнными узлами сети. |
| `RelayStorageRadius` | `20` | `1`–`100` | Радиус подключения хранилищ к реле. |
| `RelaySupplyRadius` | `20` | `1`–`100` | Радиус снабжения вокруг подключённого реле. |
| `RescanIntervalSeconds` | `2` | `0.5`–`30` | Интервал обычного пересчёта связей сети. Это не таймер каждого обновления инвентаря или запроса API. |

Кодекс запасов использует покрытие ядра или реле и не расширяет его. Изменение радиусов не требует менять рецепты.

## Хранилища

| Параметр в `[Containers]` | По умолчанию | Назначение |
| --- | --- | --- |
| `AllowedContainers` | пусто | Пусто: подключаются все подходящие хранилища. Заполнено: только перечисленные префабы. |
| `DeniedContainers` | `piece_trashcan` | Перечисленные префабы хранилищ исключаются. |
| `DeniedComponents` | См. ниже | Исключает хранилище, если в его префабе есть хотя бы один из перечисленных компонентов. |

Стандартное значение `DeniedComponents`:

```text
Incinerator,Turret,Catapult,Vagon,Ship,ItemStand,ArmorStand,Smelter,CookingStation,Fermenter,Beehive,SapCollector
```

Используйте внутренние имена префабов и компонентов, а не переведённые названия предметов. Разделяйте элементы запятыми. Пробелы вокруг имён и регистр букв не учитываются. Исключение важнее разрешения: хранилище из обоих списков останется исключённым. Эти списки фильтруют контейнеры, **а не категории ресурсов**.

Список разрешений не добавляет поддержку нестандартного инвентаря: сохраняются требования к неподвижному публичному хранилищу игрока и проверки доступа. Удаление исключённых компонентов не обеспечивает совместимость с собственной логикой инвентаря устройства. Стандартные исключения не позволяют сети забирать содержимое машин, которые расходуют его или используют как боеприпасы.

## Строительные инструменты

| Параметр в `[Building]` | По умолчанию | Назначение |
| --- | --- | --- |
| `AllowedBuildTools` | пусто | Пусто: любой инструмент с меню строительства использует сеть. Заполнено: только перечисленные префабы предметов. |
| `DeniedBuildTools` | пусто | Эти префабы инструментов никогда не строят из сетевых запасов. |
| `DeniedPieceComponents` | `TerrainOp,TerrainModifier` | Постройки с такими компонентами используют только материалы в инвентаре. |

Формат списков и приоритет исключений такие же, как для контейнеров. Разрешён должен быть именно **инструмент в руках**, даже если другое орудие использует то же меню. Изменение ландшафта по умолчанию исключено; обычные постройки, посадки и подносы могут использовать сеть.

Исключённые действия продолжают работать с материалами при себе. Если их хватает, строительство не ждёт сеть. Обычные требования к размещению и станку сохраняются.

## Диагностика и совместимость

`[Diagnostics] DebugLogging = false` — значение по умолчанию. Включите параметр для подробной диагностики операций; полное содержимое инвентарей в лог не выводится.

Консольная команда `rsn_status` (также `rsn status`) показывает состояние сети и количество поддерживаемых и исключённых типов контейнеров. Журнал мода перечисляет их по именам. Для разбора проблемы нужен лог используемого профиля; для мультиплеера по возможности приложите логи проблемного клиента и сервера.

`SupplyEnabled = true` не отменяет проверку несовместимых модов. См. [ограничения совместимости](https://github.com/rerit33/RunicStorageNetwork#несовместимые-моды-и-ограничения-интеграций). При использовании Quick Stack без MultiUserChest параметр `AllowAreaStackingInMultiplayerWithoutMUC` должен быть выключен в **конфиге самого Quick Stack**.
